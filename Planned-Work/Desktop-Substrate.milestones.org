* Introduction
  :PROPERTIES:
  :initiative_goals: A dependency-free GuiAssert core (image maths, SSIM, video segmentation, pixel window detection, the OCR interface) plus opt-in capture, OCR, accessibility-tree, input and off-screen-session backends for macOS, Linux and Windows; a `guiassert` CLI and `guiassert serve` daemon with a frozen JSON contract and a deterministic fixture backend; Agent Harbor switched onto it platform by platform once parity is measured, and its duplicated native code removed only after parity holds everywhere.
  :related_specs: [[file:Desktop-Substrate.md][Desktop Substrate spec]], [[file:Vision-Understanding.md][Vision Understanding spec]], [[file:../src/gui_assert/desktop_env.nim][desktop_env targets]], [[file:../src/gui_assert/screen_capture.nim][macOS still capture]]
  :END:

  Design, contract and rationale live in [[file:Desktop-Substrate.md]]. This
  file tracks execution, and it is the coordination point between two
  campaigns: this one (GuiAssert itself, macOS backends) and the companion
  campaign that owns every Agent Harbor change and the Linux backends. Both
  campaigns pull this file from =origin/agents= before starting a milestone and
  push their status updates to it.

  Milestones are implemented one at a time: an implementation agent (no
  commits) followed by an independent verification agent that runs the tests,
  rejects weak or skipped tests, and commits only on green.

  *Owner tags* (the =:owner:= property):
  - =substrate/macos= — this campaign, on its macOS development host (holds the
    TCC grants for live macOS evidence).
  - =companion/linux= — the companion campaign, on the organization's
    bare-metal Linux CI host; owns Agent Harbor's spec, backend crate,
    switch-over and removal, and may claim any Linux deliverable here.
  - =later/windows= — unowned until a Windows host is available; Windows
    deliverables run on the CI Windows class or that host.

  *Per-platform milestones.* GS5–GS8 each carry macOS, Linux and Windows
  deliverables. Their =:platform_status:= property records each platform
  separately (for example
  =macos=completed linux=planned windows=planned=), and the milestone =:status:= is
  =partially_completed= until all three are =completed=. A later milestone that
  needs only one platform's part names it in =:platform_prereqs:= (for example
  =GS5=macos=) and may start once those entries read =completed=, without
  waiting for the other platforms.

  *TCC.* Live macOS tests need Screen Recording / Accessibility grants for the
  signed GuiAssert helper bundle. When a grant is missing the implementing agent
  records =<milestone> BLOCKED: TCC <permission> for <binary>= in the
  milestone's Outstanding Tasks and continues with work that does not need it.

*** Deviations
    - =session-state= (spec §8.4) was not emitted as implemented: the spec
      did not say which id or =seq= it carries, since a session outlives the
      request that started it. Resolved in the review: §8.4 now makes it the
      one connection event (=id= null, a per-connection =seq=,
      =data.session=), sent when an owner session changes state on its own
      (checked every 250 ms by a prober thread running =session-info=) and
      when the daemon stops it at disconnect or shutdown; implemented and
      covered by =test_serve_session_state_events_for_owner_sessions=.
    - Byte parity of =session-start= masks =hostPid=, the pid of the newly
      started session host: two starts cannot have equal pids.
    - The vision verbs are implemented in GS2 over the pure core (their =data=
      is needed by =test_fixture_emits_every_documented_data_key=), except
      =vision-segment <video>=, which answers exit 4 (=not-implemented=;
      =not-compiled-in= in =guiassert-fixture=). GS4 implements video input
      and owns the vision tests.
    - =serve --listen unix:= is POSIX-only for now: Nim's standard library has
      no AF_UNIX on Windows, so there it answers exit 4 / =wrong-platform=;
      =--stdio= works everywhere. Follow-up with the Windows backends (GS11).
    - =--listen unix:= with an empty path means the default
      =<state-dir>/serve.sock= (the spec names the default, not its spelling).
      The state directory is made 0700 as every state directory is; a custom
      socket directory must already be 0700 and is refused otherwise rather
      than having its mode changed.
    - =ocr --image= reports the file as an =ImageRef= with =source.kind=
      ="file"=, its own size and SHA-256, =capturedAt= from its modification
      time, and =origin [0,0]= / =scale 1= (a file carries no desktop
      placement).
    - =wait= reports =elapsedMs= as the scheduled time of the matching attempt
      (=(attempt-1) * interval=), so the same wait yields the same envelope;
      the polls are paced by real time.
    - =session-stop= removes the record (a later =session-info= is exit 3);
      the returned =Session= says =stopped=.
    - In =guiassert-fixture= nothing is selected implicitly: with no selection
      the platform default applies and answers =not-compiled-in= (consumers
      set =GUIASSERT_BACKEND=fixture=).
    - =core/interfaces= gained what the verbs need: =BackendError.remedy=,
      =features= on every backend, =recordings= (capture), =focusWindow= /
      =setWindowBounds= (input), and =apps= / =launch= / =quit= /
      =permissions= (session). =core/desktop_types= gained =Permissions= and
      =Feature=.
    - =tests/tcore_purity.nim=: the per-module "the analysis saw import edges"
      sanity check exempts the modules named in =importFreeCoreModules=
      (=core/sha256=, which imports nothing). The review replaced a text
      probe for ="import "= (which a =from= import would have slipped past)
      with that explicit list, and the test now requires an exempt module to
      have zero edges and no import, from or include statement; every other
      core module must still show edges, and the allowlist check itself
      applies to all. The control on =image_math= still proves edge
      detection.
    - Review additions: every file GuiAssert reads on a caller's behalf is
      bounded (=state_store.readFileCapped=: records and scenarios 4 MiB,
      =type --text-file= 1 MiB, PNG files 256 MiB); an oversized file is
      =bad-args= / =invalid-value=. Scenario strictness (unknown keys at the
      top and nested) is now exercised by
      =test_unknown_verb_and_unknown_flag_are_bad_args=, with the oversized
      inputs.
    - Windows: the session host cannot fork; the starter keeps its own
      standard handles out of the host instead. Neither that nor any Windows
      leg has run yet.
