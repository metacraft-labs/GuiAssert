#+TITLE: GuiAssert Vision Understanding Milestones

* Document
  :PROPERTIES:
  :next_steps: VU1 first — video segmentation by visual change (SSIM). Then VU2 (OCR timeline), VU3 (query/assertion API), VU4 (window enumeration), VU5 (CLI), VU6 (flake), VU7 (apply to substrate videos).
  :last_updated: 2026-07-31
  :current_milestone: VU1
  :executive_summary: PURE computer-vision analysis (no OS APIs) that turns screenshots and recorded videos into structured, queryable, assertable descriptions, so tests (and agents) can ask — from pixels alone — "how many top-level windows are visible and what is their text?", "when did the screen change?", "did window X / URL Y appear?". This is for programs/situations where OS window APIs are unavailable (recordings, remote/VM screens, self-drawn surfaces). The separate OS-driven/appium window-enumeration capability (window_layout.nim, appium.nim) is NOT in scope here. Composes existing GuiAssert primitives (ocr.runOcr, image_math.computeSsim/decodeGray, media.resolveFfmpegBinary) into a video-analysis module, a pixel-only window detector, a query/assertion API, and a CLI. Extension of the "The Flame" home-demo campaign; validated end-to-end against the real substrate recording linux-session.mp4.
  :END:

** VU4: Window detection from pixels only (pure CV)
   :PROPERTIES:
   :status: planned
   :depends_on: VU2
   :END:

   Scope: PURE computer vision — answer "how many top-level windows + their
   text" from a single decoded frame with NO OS API. The OS-driven / appium
   window enumeration (CGWindowList / EnumWindows / wmctrl) is a SEPARATE,
   already-partially-existing capability set (window_layout.nim, appium.nim)
   and is explicitly NOT part of this initiative.

*** Deliverables
    - [ ] =gui_assert/vision_windows.nim= with =DetectedWindow= (bbox,
      titleText, text, confidence).
    - [ ] =detectWindowRects(img: GrayImage): seq[array[4,int]]= — find
      top-level window rectangles from pixels via title-bar/border edge
      projection (row/column gradient profiles) + connected-component grouping,
      filtered by min area + aspect. Pure (operates on a decoded =GrayImage=).
    - [ ] =detectWindows(framePath: string): seq[DetectedWindow]= — decode,
      detect rects, crop + =runOcr= each region → per-window title/text; answers
      "how many windows + their text" from one frame, no OS access.

*** Verification
    - [ ] =test_detect_window_rects_synthetic=: build a synthetic =GrayImage=
      in-memory with two drawn window rectangles → =detectWindowRects= returns
      exactly two rects at the expected positions (±tolerance).
    - [ ] =e2e_windows_from_substrate_frame=: on a real keyframe extracted from
      linux-session.mp4 that shows the terminal + file-manager, =detectWindows=
      reports >= 2 windows whose OCR text includes the terminal's "flame" log
      and the file-manager path — from pixels alone. Real ffmpeg + tesseract.
