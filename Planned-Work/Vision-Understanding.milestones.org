#+TITLE: GuiAssert Vision Understanding Milestones

* Document
  :PROPERTIES:
  :next_steps: VU1-VU4 completed. NEXT: VU5 (token-efficient agent index + grep/extract CLI — highest leverage per the SOTA survey), then VU6 (flake), VU7 (substrate tie-in). Then hardening from the SOTA survey: VU8 (tiled SSIM + pHash dedup + ECR), VU9 (OCR upscale + dark-mode inversion + per-region PSM), VU10 (classical layout tree: morphology/Hough/MSER/projections), VU11 (optional Apple Vision / RapidOCR / OmniParser backends behind flags). Finish with a SKILL.md documenting the tooling for agents.
  :last_updated: 2026-07-31
  :current_milestone: VU1
  :executive_summary: PURE computer-vision analysis (no OS APIs) that turns screenshots and recorded videos into structured, queryable, assertable descriptions, so tests (and agents) can ask — from pixels alone — "how many top-level windows are visible and what is their text?", "when did the screen change?", "did window X / URL Y appear?". This is for programs/situations where OS window APIs are unavailable (recordings, remote/VM screens, self-drawn surfaces). The separate OS-driven/appium window-enumeration capability (window_layout.nim, appium.nim) is NOT in scope here. Composes existing GuiAssert primitives (ocr.runOcr, image_math.computeSsim/decodeGray, media.resolveFfmpegBinary) into a video-analysis module, a pixel-only window detector, a query/assertion API, and a CLI. Extension of the "The Flame" home-demo campaign; validated end-to-end against the real substrate recording linux-session.mp4.
  :END:

** VU4: Window detection from pixels only (pure CV)
   :PROPERTIES:
   :status: completed
   :status_note: vision_windows.nim landed with DetectedWindow + pure detectWindowRects (Otsu threshold → iterative stack flood-fill connected components → min-area/aspect filtering → nested-box merge → top-left→bottom-right sort) and effectful detectWindows (decode → detect → ffmpeg crop per rect + top band → runOcr; confidence = bbox fill ratio; honors FFMPEG/FFMPEG_BIN/PATH/TESSERACT_BIN; temp files cleaned). NO OS window API. Tuned defaults: minAreaFrac=0.015 (windows ≫ this, specks ≪), maxAreaFrac=0.98 (rejects the whole-frame background blob — this is what makes a unimodal/blank frame yield 0 windows since Otsu degenerates to threshold 0 on it), maxAspect=12.0 (rejects slivers), 8-connectivity. Tests in tests/tvision_windows.nim: test_detect_window_rects_synthetic (pure, in-memory GrayImage, exactly 2 rects ±6px + blank/black → 0) and e2e_windows_two_window_frame (real ffmpeg-rendered 1000x700 desktop PNG, real tesseract; exactly 2 windows at expected positions, per-window OCR contains its distinct ALPHA/BETA label and not the other's) both green; optional GUIASSERT_SUBSTRATE_MP4 block is genuinely conditional. Full suite: tvideo_analysis 11/11 + tvision_windows 2 required (+1 optional) green with real ffmpeg + tesseract 5.5.2.
   :depends_on: VU2
   :END:

   text" from a single decoded frame with NO OS API. The OS-driven / appium
   window enumeration (CGWindowList / EnumWindows / wmctrl) is a SEPARATE,

** VU9: OCR quality (upscale + dark-mode inversion + per-region PSM + confidence)
   :PROPERTIES:
   :status: completed
   :depends_on: VU2
   :status_note: Implemented in src/gui_assert/ocr.nim WITHOUT changing the
     legacy runOcr contract (bboxes stay in original space; existing suites
     green). Added OcrOptions{psm, upscale, invert(oiAuto|oiNever|oiAlways),
     contrast}, initOcrOptions() (defaults psm=6, upscale=1.0, oiAuto, no
     contrast), runOcrEx (ffmpeg preprocess: Lanczos scale=iw*U:ih*U:flags=
     lanczos with bboxes divided back by U to ORIGINAL space; negate for
     dark-mode; light eq=contrast=1.3), and runOcrMultiPsm (runs each PSM, e.g.
     @[6,11], merging unique words deduped by (text, bbox≈±6px)). analyzeVideo
     now OCRs each keyframe via runOcrMultiPsm(@[6,11], upscale=2.0, oiAuto)
     (exposed as ocrPsms/ocrOpts params). Auto-invert luma threshold = 110.0
     (mean grayscale via image_math.decodeGray; below → invert). Upscale default
     2.0 in the pipeline (tests use 3.0 for the tiny-font case).
     KEY DESIGN / FINDING: modern tesseract (5.5.2) has a built-in polarity
     heuristic (tessedit_do_invert, ON by default) that silently re-inverts
     light-on-dark text, so a naive oiNever "worked" anyway and the option was
     neither testable nor authoritative. runOcrEx now sets tessedit_do_invert=0
     so OcrOptions.invert is the single deterministic source of truth; runOcr
     keeps tesseract's auto-invert ON and is left byte-identical (the
     white-on-black fibonacci OCR test in tgui_assert stays green).
     Tests: tests/tocr_vision.nim (real ffmpeg + real tesseract, no mocks; both
     failing and passing directions asserted): e2e_ocr_dark_mode (oiNever reads
     garbage "DL (o]0 =5 W 1))" — no DARKMODE/4242 — while oiAlways/oiAuto read
     "DARKMODE TEXT 4242"); e2e_ocr_upscale_small_text (fontsize-9: 1x reads
     "TowscaLe a1", 3x reads "TINYSCALE 7731"); test_bbox_rescale (upscale=3
     bboxes land within the original 480x120 bounds, not ~3x); regression
     runOcr dark-on-light; runOcrMultiPsm dedup (3 words, no doubling). All 5
     pass; tvideo_analysis 11/11, tvision_windows 3/3, tvision_cli 5/5,
     tgui_assert OCR OK. REAL VIDEO: on the 49.72s linux-session.mp4 the base
     analyzeVideo now surfaces Browser + Replay + CodeTracer (containsText true
     for each) that the VU7 single-psm-6 pass dropped — "Browser Replay" as an
     exact adjacent phrase is still false because the client title wraps to
     separate reading-order lines ("browser-"/"replay"), but the tokens are now
     in the index/digest without the verifier-side workaround. ~68s for the 49s
     clip (9 states x 2 PSMs x 2x upscale). Per-region PSM selection wired to a
     window/region detector (VU4/VU10) and confidence-in-index are left as
     follow-ups; the multi-PSM merge is the shipped VU7-gap fix.
   :END:
